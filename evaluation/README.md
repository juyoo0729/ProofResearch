# 원문 기반 비교 평가 v1

이 평가는 세 기업의 제한된 공시에서 구현 동작을 비교하는 **내부 평가**다. 원문에서 금액을 별도로 전사해 정답을 먼저 작성했으며 생산 계산 결과를 정답으로 사용하지 않는다. 다만 개발 보조 AI가 정답 작성·검토도 맡았고, 개발 중 이 기업들의 공시를 이미 열람했다. 외부 전문가의 독립 평가나 처음 보는 기업으로의 일반화 검증이 아니다.

## 구성과 정답

- `gold.json`: 개발 20문항(수치 12·서술 4·보류 4), 평가 40문항(수치 24·서술 8·보류 8).
- 수치 정답은 9개 10-K 원본의 연결 손익계산서에서 매출·영업이익·전기 매출을 직접 전사했다. XPath, 셀 ID, 문서 해시, 백만 USD 표시값을 보존하고 별도의 Decimal 산식으로 비율을 계산했다.
- 개발 수치는 AMD·Intel의 2023년 말, NVIDIA의 2024년 1월 종료 기간이다. 평가 수치는 이후 각 두 연차기간이다. 대상 기간은 겹치지 않지만 같은 기업·공시군이고 비교연도 금액이 재등장하므로 통계적으로 독립인 60개 표본이라고 보지 않는다.
- 평가 보류는 기간/계정이 다른 직접 비교 4문항과 기준일에 제출되지 않은 기간 4문항이다. 동일 원인으로 묶이는 문항이 있으며 단위 변조·악성 문서·모든 수정공시 유형까지 검증하는 것은 아니다. 그 외 반례는 합성 입력 자동 테스트로 구분한다.
- 서술 정답은 관련 원문의 인과관계와 조건부 위험을 기준으로 검토한다. 예시 문단 외의 근거도 회사·보고기간이 맞고 실제 주장을 뒷받침하면 인정한다.

## 비교 방법

세 방법 모두 GPT-6 Luna, reasoning low, 같은 로컬 모델 가격·예산 설정, 동일한 SEC 스냅샷을 사용한다. 재무 표를 읽는 코드와 공시 선택 규칙은 공유한다. 따라서 원문 추출기 자체의 우열을 비교하는 실험은 아니다.

| 방법 | 입력과 계산 | 모델 호출 |
| --- | --- | --- |
| 단일 요약 | 선택된 원본 손익계산서의 셀·기간·단위와 고정 순서 Risk Factors 묶음. 큰 묶음은 약 110KB 예산에 맞춰 일정 간격으로 선택하며 실제 입력을 저장한다. LLM이 비율 계산과 보류 판단 | 1회, 자동 재시도 없음 |
| RAG | 같은 손익계산서 셀 + 질문으로 SQLite FTS5 검색한 기업별 최대 3개 원문 문단. LLM이 비율 계산과 보류 판단 | 1회, 자동 재시도 없음 |
| Agent | 제품의 실제 수집·검산·문단 검색·재탐색·종료 도구 흐름. 코드가 Decimal 수치를 계산하고 비교 조건을 검사 | 최대 6회, 도구 12회, 재탐색 2회, 180초 |

단일 요약은 전체 10-K를 무제한으로 입력하는 방식이 아니다. RAG는 임베딩이 없는 어휘 검색 기준선이다. Agent와 문맥 길이·호출 수가 같지 않으므로 비용·시간도 함께 비교한다. 각 방법을 한 번씩 실행하며 확률적 변동이나 다회 반복 신뢰구간은 측정하지 않는다. 순서는 문항 ID와 방법 이름의 해시로 섞는다.

질문의 기업·기준일·대상 기간·지표는 세 방법 모두 공개 입력이다. 정답, 답변 가능 여부, 예시 근거, 채점 기준은 모델에게 전달하지 않는다. Agent는 화면의 구조화 보고서에서 요청 기간/지표를 추출해 채점한다. 대상 기간이 없으면 다른 연도의 값을 대입하지 않고 보류한다. 이는 자유형 질문의 모든 의도를 화면이 자동 추출한다는 평가가 아니다.

## 채점

- 수치 정확도: 정답 수 / 유효 수치 응답 수. 유효 응답률: 유효 수치 응답 수 / 답변 가능 수치 문항 수. 함께 정답 수 / 전체 수치 문항 수도 보고한다.
- 금액은 USD 원 단위 오차 0.5 이내, 비율은 0.005%p 이내. 원래 값·음수 부호·기간·단위가 맞아야 한다.
- 수치 인용: 원문 구절, 기업, 보고기간이 맞고 산식에 필요한 원문 셀 ID를 모두 제시해야 해당 문항을 성공으로 센다. 서술 인용은 구절 일치에 더해 의미가 주장을 뒷받침하는지 별도 검토한다.
- 인용 성공률은 답변 가능 수치·서술 문항 전체를 분모로 하는 엄격한 문항 단위 지표다. 인용 하나의 정밀도와 같지 않으며, 응답 보류/인용 누락도 실패로 센다.
- 보류는 정상 완료, 활용 가능한 공시, 올바른 보류 상태와 관련 사유를 요구한다. API/시간초과 실패를 올바른 보류로 집계하지 않는다.
- 정성 검토는 정답 작성과 같은 개발 보조 AI의 검토다. 원문을 다시 읽고 조건부 표현·질문 관련성·추가 주장을 확인하지만 평가자 독립성은 없다. 외부 검수 전 성능의 확정 증거로 표현하지 않는다.
- 시간은 각 문항의 원문 처리·모델 호출·Agent 프로세스 시작을 포함한 벽시계 시간이다. 이미 동결된 로컬 자료를 사용하므로 SEC 실시간 다운로드 지연은 포함하지 않는다.
- 비용은 실제 반환 토큰과 누적 예약 장부를 사용한다. USD당 2,000원과 가격 할증을 적용한 보수적 예산 환산이며 카드 청구액이 아니다.

## 실행과 동결

```powershell
# 먼저 SEC 원문을 확보한 로컬 작업 폴더에서 1회만 준비
uv run python -m evaluation.run prepare
uv run --env-file .env python -m evaluation.run run --split dev
uv run python -m evaluation.run score --split dev

# 개발 절차 점검이 끝난 뒤 정답·코드·자료 목록을 동결
uv run python -m evaluation.run freeze
uv run --env-file .env python -m evaluation.run run --split eval
uv run python -m evaluation.run score --split eval
```

`freeze.json`이 생긴 뒤 정답·자료 목록·실행 코드가 바뀌면 평가 호출을 거절한다. 평가용 DB는 읽기 전용이며 오래된 자료 또는 refresh 요청이어도 네트워크로 보충하지 않는다. 개별 실행은 `.cache/evaluation-v1-results/`에 저장되고 중단 후 이어서 실행할 때 기존 결과를 덮어쓰지 않는다. 실패도 기록에 남으며 좋은 답변을 고르기 위한 재실행은 하지 않는다.

원문 DB와 실행 응답은 Git에 올리지 않는다. 공개된 해시 목록만으로 나중에 변한 Company Facts의 과거 내용을 복원할 수 없으므로 정확한 재현에는 보존된 로컬 동결 자료가 필요하다. 새 자료로 다시 실행하려면 별도 버전으로 평가해야 한다. 사용자 검토·수정 시간과 30% 절감 효과는 이 자동 실험에서 측정하지 않는다.
