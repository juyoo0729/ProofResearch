# 실행 환경과 공개 데모 준비

**2026-10-12 운영 결정:** 사용자는 서버·도메인이 없는 상태이며, 공개 배포는 1차 심사 합격을 확인한 뒤 진행한다. 현재는 로컬 실행 화면 디자인만 다듬는다. 서버 구매·도메인 등록·외부 URL 발급은 수행하지 않았다. 인증·장부 보존을 확인한 배포 초안은 로컬 작업 폴더에 보관하고 활성화하지 않았다.

기본 실행은 README의 Python 3.12·uv 절차다. Windows 외 환경은 GitHub Actions의 Ubuntu·Windows 검사로 확인하고, 각 변경에 해당하는 실행 링크를 기록한다. 컨테이너 구성은 동일한 `uv.lock`을 설치한다. [uv 공식 Docker 안내](https://docs.astral.sh/uv/guides/integration/docker/)를 따른다.

## 로컬 컨테이너

Docker Desktop 또는 Docker Engine이 실행 중이어야 한다. `.env.example`을 `.env`로 복사해 로컬 설정을 채운다. 키 없이도 가상 예제는 동작한다.

```powershell
docker compose config --quiet
docker compose build
docker compose up -d
```

브라우저에서 `http://127.0.0.1:8502`를 연다. 기본 구성은 로컬 컴퓨터에만 연결되며 인터넷 공개 주소를 만들지 않는다. 종료는 `docker compose down`이다. `.cache` 폴더를 지우지 않는다.

키와 연락처는 이미지에 복사하지 않고 실행할 때만 환경변수로 전달한다. 이미지에는 코드·의존성만 포함한다. 모델 비용 장부와 SEC 캐시는 호스트의 `.cache`를 사용하므로 컨테이너를 교체해도 유지한다. 단일 인스턴스 안에서는 같은 캐시 DB를 사용하는 작업 프로세스들이 초당 두 번의 SEC 요청 슬롯을 공유한다.

## 공개 배포 전 확인할 항목

- 공개 대상: 실행 가능한 Streamlit 화면과 이미 공개된 GitHub 코드. 계정 로그인, 서버/도메인, 월 호스팅 비용은 아직 정하지 않았다.
- 운영 방식: 단일 인스턴스·영속 디스크에 `.cache/usage.sqlite3`와 SEC 캐시를 보존한다. 일시적인 파일 시스템만 있는 호스팅에서 재시작할 때 장부를 초기화하는 방식은 사용하지 않는다.
- 비용 범위: 요청당 500원, 전체 실험 50,000원은 누적 상한이다. 기존 실험 사용량을 포함한 장부를 이전한다. 여러 호스트가 서로 다른 장부로 같은 예산을 중복 사용하지 않도록 기존 인스턴스를 중지한 후 이전한다.
- 접속 제어: 심사자 공개 범위·동시 사용량·인증 여부를 배포 대상에 맞춰 결정한다. API 키와 SEC 연락처를 제공하는 호스팅 사업자는 참가자가 확인한다.
- 운영 점검: 재시작 후 비용 잔액 유지, 원문 조회, 다운로드, 정상 비교/보류/재탐색, 요청 한도 종료를 배포 환경에서 다시 확인한다. 가격 검토가 만료되면 실제 공식 가격을 확인해 기록을 갱신한다.
- 공개·최종 제출: 준비한 화면과 문서를 검토하고 사용자가 승인한 뒤 수행한다. 로컬 실행 또는 컨테이너 준비를 인터넷 배포 완료로 표현하지 않는다.

동결 평가의 원문 DB는 일반 갱신 캐시와 분리한다. 추후 SEC 응답이 바뀌면 기존 평가 원문을 덮어쓰지 않고 새 자료·새 평가 버전을 만든다. 제출용 Git 저장소에는 키·연락처·원문 캐시·상세 실행 보고서를 넣지 않는다.


## 2026-10-12 로컬 컨테이너 검증

고정 이미지로 빌드한 Python 3.12.15 Linux 환경에서 합성 예제와 실제 SEC 캐시 검산을 실행했다. 실제 24개 지표 PASS, 결산기간·계정 차이로 기업 간 비교 HOLD를 확인했다. 비루트 사용자, 이미지 안 `.env` 없음, 건강 상태 정상, 컨테이너 재시작 전후 기존 호출 장부 436건 보존을 확인했다. 기존 Windows 화면에서도 두 연차기간의 증가율을 확인했다.

컨테이너의 새 LLM 호출은 API 잔액 복구 전 검증하지 않았다. 검사 후 컨테이너를 중지하고 Windows 로컬 화면만 남겼다. Windows 실행과 Linux 컨테이너 사이의 파일 잠금 상호운용은 검증하지 않았으므로 유료 운영은 한 런타임만 활성화한다. 같은 환경 안의 여러 Python 프로세스 제한은 자동 검사로 확인했다.
