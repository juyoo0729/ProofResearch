## 제출 검토용 시연 자료

로컬 `결과물/ProofResearch_실제실행기록_해설_90초.mp4`에 위 세 실제 실행 기록을 90초 무음 해설 영상으로 구성했다. 1280×720 H.264, 24fps, 전체 디코딩 검사를 통과했다. 실제 화면 녹화나 실시간 API 재실행이 아니라 저장된 결과의 해설이다. 각 장면에 이 구분과 실제 처리시간을 별도로 표시한다.

`결과물/실행기록_시연/scene-0.html`부터 같은 자료를 클릭해서 확인할 수 있고 원래 HTML 보고서 세 개가 연결된다. 원본 실행은 21개 지표를 검사하던 버전이다. 현재 구현은 두 연차 모두 증가율을 포함해 24개를 검사하며 예전 로그를 최신 실행으로 바꾸지 않았다.

2026-10-12 추가 검증: Windows 실제 공시 화면에서 AMD 이전 연도 13.69%, Intel -2.08% 증가율을 확인했다. Linux Docker의 실제 SEC 캐시 검산도 24 PASS·기업 간 비교 HOLD였다. Docker의 새 LLM 실행은 잔액 복구 전 수행하지 않았다.

미완료: 별도 전체 평가, 공개 데모 URL, 외부 사용자 검토와 검토시간 실측. 공개 영상 업로드와 최종 제출은 하지 않았다.

## 유료 API 작동 재점검

2026-10-12 사용자의 추가 요청으로 GPT-6 Luna 최소 연결 호출과 Windows 실제 화면 분석 두 건을 수행했다. 요청당 500원·전체 50,000원 한도와 기존 비용 장부를 유지했다. SEC 원문은 캐시를 사용했고, LLM은 실제 API를 호출했다. 아래 실행을 v1 평가의 실패 대신 넣거나 평가 성적에 합산하지 않는다.

최소 연결은 1회·0.010450원이었다. 추가 합계 9회·11.809875원, 프로젝트 누적 445회·824.693375원, 미확정 호출 0회다. 모두 토큰 사용량의 보수적 예산 환산이며 실제 카드 청구액이 아니다.

첫 실행에서는 기업·인용 불일치가 차단됐고, 수정된 설명의 일반어 ‘제3자’도 숫자 검사에 걸렸다. 모델은 이후 설명을 비워 종료했다. 실행 상태 `completed`를 설명 생성 성공으로 해석하지 않는다. 두 번째 실행에서는 설명의 인용 ID·기업·구절 일치, 브라우저 표시와 HTML·JSON 다운로드를 확인했다. 설명은 해당 문단의 문맥을 사용하므로 짧은 인용 구절만으로 모든 주장을 뒷받침하는지는 후속 검토가 필요하다.

## 숫자 오탐 수정과 후속 확인

같은 날 사용자가 요청한 디버깅에서 `제3자`의 숫자를 정량 주장으로 오인하는 원인을 수정했다. 단어 자체와 흔한 조사 형태만 검사할 때 정규화하며, 출력 문장은 바꾸지 않는다. 실제 숫자·금액·비율과 인용 ID·기업·정확 구절 검사는 유지한다. 허용 목록 밖의 표현은 계속 보류될 수 있다.

실패 실행의 두 번째 완료 후보는 세 기업 모두 인용이 유효했으나 INTC의 `제3자` 때문에 전체가 거절됐다. 해당 후보를 오프라인 재생해 수정 후 설명 3개가 그대로 유지됨을 확인했다. 정상 표현·실제 수치·잘못된 인용의 회귀 사례 12개를 추가했고 전체 자동 검사 114개가 통과했다.

그 뒤 같은 세 기업·기준일·기본 질문으로 실제 API 분석을 **한 번** 수행했다. 로컬 근거는 `reports/9ae5ec7c83c94d539194c45aefad43ae`다.

| 결과 | LLM / 도구 / 재탐색 | 시간 | 예산 환산 |
| --- | --- | --- | --- |
| 재무 지표 24개 규칙 통과, 기간·계정 조건으로 비교 HOLD, 설명·인용 3개, 도구 입력 거절 없음 | 3 / 3 / 0 | 16.828초 | 3.931675원 |

인용 ID·기업·구절 일치를 확인했고 HTML·JSON·CSV 보고서를 저장했다. 이 새 응답에는 `제3자`가 없었으므로 해당 표현의 수정 효과는 앞의 오프라인 재현과 반례 검사로 확인한 것이다. API 실행 성공을 독립적인 의미 정확도나 Agent 성능 우위로 해석하지 않는다. 프로젝트 누적 장부는 448회·828.625050원, 미확정 0회이며 실제 카드 청구액이 아닌 보수적 예산 환산이다.

v1 동결 해시·정답·자료·120회 결과는 그대로 보존했다. 보존본의 재채점 파일과 집계는 이전 바이트와 일치한다. 수정된 제품에서 v1 평가를 새로 실행하면 코드 불일치로 거절되므로 [당시 코드와 자료의 재현 절차](../evaluation/README.md#오류-수정-이후-v1-재현)를 사용한다. 별도 전체 평가·Docker 유료 실행·공개 배포는 하지 않았다.
