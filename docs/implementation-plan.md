# 기획안에서 구현으로

기준: 2026-10-11 작성된 기존 「ProofResearch 기획안」 본문. 이 문서는 구현 상태를 관리하며 제출용 원본의 성능 목표를 달성 실적으로 바꾸지 않는다.

## 다음 작업 순서

1. 공시 원문으로 정답 60문항을 작성하고 개발 20/동결 40으로 분리한다. 계산 도구의 출력으로 정답을 대신 만들지 않는다.
2. 단일 요약·RAG·Agent를 같은 자료와 모델로 비교한다. 수치 정확도·유효 응답률·인용 의미·보류·시간·비용과 실패 사례를 함께 기록한다.
3. 임베딩 검색의 필요성을 개발셋에서 확인한다. 사용자 검토·수정 시간을 실제 측정할 수 있을 때만 단축 효과를 계산한다.
4. 다른 환경 재현과 배포 환경의 시간·동시 요청·누적 비용 제한을 검증한다. SEC 요청 제한을 여러 프로세스에 통합한다.
5. 기존 공식 양식의 예선 PDF, 본선 발표·Q&A·영상과 데모 URL을 준비한다. 공개·최종 제출은 승인 범위 안에서 별도로 수행한다.

## 설계 선택

- 기획서의 기술 스택과 기존 폴더를 유지한다. 별도의 프런트엔드 프레임워크나 다중 Agent는 도입하지 않는다.
- 현재 모델이 없는 수집·계산 기준선을 완성한 뒤 RAG와 Agent를 비교할 수 있도록 한다. 합성 예제를 캐시 또는 실시간 금융자료로 표시하지 않는다.
- 10-K/A에 없는 값은 기본적으로 보류한다. 개발 중 읽은 AMD 수정 설명 1건만 원문 SHA-256과 원본 accession을 고정해 등록했다. 해시·기업·기간·제출 순서가 일치할 때 원본 연결 재무 표를 대조하고 수정본을 함께 표시한다. 이를 모든 수정 공시에 적용하는 자동 판독으로 표현하지 않는다.
- 전기 매출은 최신 선택 공시에서 찾는다. 직전 공시의 값과 다를 수 있으므로 재작성된 비교 수치를 조용히 섞지 않는다.
- 직접 비교 가능 판정은 기간·통화·정량 계정 조건에 한정된다. 기업들의 사업구조가 동질적이라고 주장하지 않는다.
- 화면은 흰색 바탕, 청색 강조 `#195CB0`, 잉크색 본문 `#17314D`, 옅은 청색 `#EDF3FA`, 보류용 황갈색 `#A66A00`을 사용한다. 한국어 시스템 글꼴로 왼쪽 정렬하며 비교표 아래 근거를 펼친다. 그림·애니메이션보다 보고기간과 수치의 가독성을 우선한다.
- Agent 전체는 별도 프로세스로 감싸 180초에 강제 종료한다. 단독 검산 CLI의 동기 HTTP 제한은 기존과 같이 읽기 중 추가 지연이 가능하다. Agent 종료는 2초로 축소한 멈춤 작업에서 실제 프로세스와 후속 쓰기가 멈추는지 검사했다. 180초 전체 대기·호스팅 환경 검증은 별도다.

## 검증의 경계

자동 테스트는 코드 회귀를 검증한다. 별도 정답셋, 라이브 연결, 원문 인용 정확도, 검토시간 30% 단축, 수치 정확도 95%는 각각 독립적으로 검증해야 한다. 현재 이러한 성과를 달성했다고 주장하지 않는다.

- `uv run pytest`: 77개 통과. 다른 기업·기간·통화·분기값, 충돌하는 중복, 숨긴 표, 지원하지 않는 숫자 형식, 원문 누락, 수정본 해시 변경 시 보류를 검사했다.
