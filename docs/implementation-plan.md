# 기획안에서 구현으로

기준일 2026-10-13. 기존 공식 양식 기획안과 Python·Pydantic·Streamlit·SQLite 구조를 유지한다. 구현·연결·내부 평가·외부 검수·최종 제출은 각각 구별한다.

사용자 결정에 따라 1차 심사 전에는 실행 화면 디자인을 개선하고 오류를 점검한다. 색상·글자·입력 영역·결과 탭·모바일 배치를 정리하고, 공백 입력과 저장소 오류의 화면 처리를 보완했다. 후속 디버깅으로 Agent의 ‘제3자’ 숫자 오탐도 수정했다. 검산·검색·동결 평가 절차는 유지한다. 추가 기능·후속 전체 평가·공개 배포는 1차 심사 합격 확인 후 재개한다.

2026-10-12 추가 요청에 따라 유료 API 작동 점검은 수행했다. 연결 복구와 Windows 화면의 두 분석을 확인했으며, 기존 동결 120회 평가와 합산하지 않았다. 기본 질문의 설명 보류와 ‘제3자’ 숫자 오탐 및 후속 수정 검증을 [실행 기록](demos.md#유료-api-작동-재점검)에 남겼다. v1은 당시 코드와 원문·응답 보존본에서 재현한다.

예선 기획안은 제출 완료이며 수정하지 않는다(2026-10-12 사용자 확인). 제출본의 버전·접수 내역은 별도로 확인하지 않았다. 제출 상태를 잘못 이해하고 만든 v4(PDF·PPTX·본문)는 내부 참고본으로만 보존하며, 후속 API 점검 결과가 실제 제출본에 반영되었다고 주장하지 않는다. 기존 v1~v3와 동결 평가의 80회 완료·40회 오류 기록은 보존한다. 참가자 상호 평가의 최소 투표 횟수는 구체적인 공지가 필요하다.

2026-10-12 사용자는 컴퓨터를 꺼도 GPT가 개발·오류 점검을 계속하는 클라우드 작업을 요청했다. 같은 ChatGPT 프로젝트의 ‘클라우드 검사 결과’ 채팅에서 Python 3.12.14·uv 0.12.4 설치, 오프라인 검사 114개, 합성 A·B PASS/A·C HOLD와 Streamlit HTTP 200을 확인했다. 2026-10-13 해당 명령·종료 코드·출력을 대조하여 [실제 클라우드 검사 기록](cloud-development.md)에 반영했다. 클라우드의 GitHub 쓰기 인증이 없어 이 기록은 기존 로컬 인증으로 반영하며, 상시·예약 작업은 설정하지 않았다. 별도 서버를 구매하지 않았으며 공개 앱 배포와 전체 재평가의 합격 이후 조건은 유지한다.

2026-10-13 로컬 브라우저에서 390px·320px 화면, 정상·기간 불일치·공백 입력 후 복구, 근거·실행 기록 열람과 HTML·CSV·JSON 실제 다운로드를 확인했다. CSV 16개 행과 JSON의 값·단위·판정이 일치했고 새 앱 오류는 재현되지 않았다. [화면 점검 기록](ui-checks.md)에 범위를 남겼으며, 실제 휴대폰·클라우드 브라우저 검증과 외부 사용성 평가는 아직 수행하지 않았다.

같은 날 후속 코드 점검에서 명령 실행의 공백 질의가 성공으로 종료되고 보고서를 생성하는 문제를 재현했다. 화면에만 있던 공백 차단을 공통 `ResearchRequest` 검증에도 적용했다. 공백·줄바꿈·탭·유니코드 공백 반례와 합성/SEC/Agent 명령 경로를 검사했으며, 실행 함수 호출·파일 생성 전에 차단했다. 수정 전 실패한 반례 5개가 수정 후 통과했고 Windows 전체 오프라인 검사는 119개 통과(11.42초)였다. 유료 API·실제 SEC 호출 없이 검증했고, 공시 선택·계산식·v1 동결 기록은 변경하지 않았다.

명령 실행에서 손상된 SQLite 저장소의 내부 오류가 그대로 노출되는 문제도 임시 SEC 캐시로 재현했다. 캐시·비용 장부의 데이터베이스 오류를 한국어로 안내하고 종료 코드 1을 반환하도록 수정했다. 실제 손상 파일을 사용하는 두 반례에서 파일 보존·보고서 미생성·후속 가상 예제 실행을 확인했다. 네트워크 호출을 금지한 검사이며 Agent 경로는 비용 장부 생성부를 사용한 모의 실행이다. Windows 전체 오프라인 검사 121개가 통과(11.05초)했고 실제 비용 장부는 건드리지 않았다.

2026-10-13 연결된 GitHub 앱에서 계정과 저장소 쓰기 권한을 확인하고, 이 문서·README·클라우드 인계 문서를 앱의 Git 데이터 API로 저장했다. [후속 저장 절차](cloud-development.md#연결된-github-앱으로-저장)를 추가했다. 이 검증은 로컬 Codex 채팅에서 호출한 앱 연결의 저장 성공이며, 클라우드 터미널 인증 설정이나 기존 클라우드 채팅에서의 저장 재현 완료를 뜻하지 않는다.

## 현재 평가의 해석

Agent 수치 정답은 응답된 12문항에서 12개다. 그러나 전체 24개 대비 응답률은 50%, 인용 타당 문항은 14/32, 보류는 6/8이다. 18개 Agent 실행은 API 잔액 오류로 실패했다. 단일 요약·RAG도 각각 12·10개 실패했으므로 정상 응답만 골라 우위를 주장하지 않는다. 서술 인용 두 건의 추가 주장·한정 누락과 RAG 계산 한 건의 반올림 오류를 기록했다. 자세한 분모와 제한은 [평가 결과](evaluation-results.md)를 따른다.

## 다음 작업

아래 후속 작업은 **1차 심사 합격 확인 이후**의 목록이다. 충전 안내만으로 배포나 후속 평가를 자동 재개하지 않는다.

1. 유료 API 연결 복구와 ‘제3자’ 오탐 수정은 확인했다. v1 기록을 보존한 별도 전체 평가를 계획하고, 남은 설명 보류·의미 인용 사례를 검증한다. 성공 사례와 재시도 성공만 합쳐 평가하지 않는다.
2. 본선 검토안·대본·영상을 별도 전체 평가와 외부 검토 결과에 맞춰 갱신한다. 내부 참고본 v4에 반영한 단일 작동 점검을 새 평가 성적으로 사용하지 않는다. 품질 목표 미달은 공개한다.
3. 담당자의 원문 확인·수정까지 포함한 [사용자 검토시간 과제](user-study.md)를 수행할 때만 30% 단축 여부를 판단한다.
4. 준비된 [Docker 실행 환경](deployment.md)의 공개 대상·호스팅·비용·비밀 설정을 확정하고 공개 배포 승인을 받는다. 실행 URL을 얻은 뒤 실제 외부 환경에서 세 흐름을 점검한다.
5. 본선 제출 전 공식 일정·접수 명칭·AI 활용 표기를 확인한다. 이미 제출된 예선 기획안은 수정하지 않는다. 참가자 상호 투표는 사용자가 직접 수행한다.

## 설계 선택과 검증 경계

- 재무 수치와 비율은 코드가 계산한다. 자유형 질문의 모든 의도를 UI가 자동 추출하는 제품은 아니며 평가는 구조화 보고서에서 대상 기간·지표를 추출한다.
- 두 연차 모두 해당 공시의 비교 매출을 쓴다. 다른 공시의 값으로 누락을 조용히 메우지 않는다.
- 매출 계정·기간·통화 일치는 기업 사업구조의 동질성을 의미하지 않는다. 부문·사용자 정의 계정·비GAAP·환산은 제외한다.
- Agent 전체를 별도 프로세스로 실행하고 180초에 종료한다. 자동 검사는 시간을 축소한 멈춤 작업으로 검증했으며 실 배포의 180초 대기 시험은 별도다.
- Windows 로컬 자동 검사 121개는 회귀 방지 증거다. 화면·명령·공통 요청의 공백 입력 차단, 화면·명령에서 손상된 캐시·비용 장부의 오류 안내와 파일 보존, 기업·날짜 누락, 모드 전환과 실패 후 복구, ‘제3자’ 표현의 허용과 실제 수치·잘못된 인용 차단을 포함한다. 자동 검사의 API 오류는 모의이며, 위 실제 유료 작동 점검과 구분한다. 원문 표 대조, 독립 정확도, 외부 사용자 시간 절감과 같은 성과로 바꾸어 표현하지 않는다. 초기 클라우드의 114개 결과는 별도 기록이며 후속 코드 변경의 클라우드 재검사는 아직 수행하지 않았다.
- 초기 77·89개 검사와 21개 지표 시연은 당시 버전의 기록이다. 현재 두 연차 지표는 24개이며 예전 보고서를 최신 실행인 것처럼 표시하지 않는다.
- 정답·평가 코드·원문 스냅샷의 동결 해시는 보존한다. 잔액 오류를 고치기 위해 v1 정답이나 채점기를 바꾸지 않는다.
