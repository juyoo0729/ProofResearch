# 기획안에서 구현으로

기준: 2026-10-11 작성된 기존 「ProofResearch 기획안」 본문. 이 문서는 구현 상태를 관리하며 제출용 원본의 성능 목표를 달성 실적으로 바꾸지 않는다.

## 다음 작업 순서

1. 연락처를 정하고 실제 SEC 응답을 수집한다. 각 기업의 2개 연차공시와 표준 계정 매핑을 수작업 대조한다. 실제 데이터의 PASS·HOLD 사유를 기록한다.
2. 10-K HTML의 표·문단을 수집하고 공시 ID·섹션·원문 위치·해시를 보존한다. 표 수치와 Company Facts 값을 대조한다.
3. 기업·공시 필터를 코드에서 고정한 키워드 검색을 만든다. 임베딩 검색을 추가하고 정성 주장에 원문 구간을 연결한다.
4. 중앙 Agent에 검증된 도구만 연결한다. 실행계획·재조회·다른 문단 검색·보류를 결정하게 하고 임의 코드 실행은 허용하지 않는다. 12 도구 호출·6 LLM 호출·2 재탐색·180초를 요청 전체에서 관리한다.
5. 공시 원문에서 독립적으로 만든 정답셋을 동결하고 단일 요약·RAG·Agent를 같은 자료와 모델로 비교한다. 답변률과 정확도를 함께 기록한다.
6. 정상 비교·기간 불일치·근거 재탐색을 시연하고 비용을 측정한다. 재현 환경과 배포, 최종 PDF·영상을 준비한다.

## 설계 선택

- 기획서의 기술 스택과 기존 폴더를 유지한다. 별도의 프런트엔드 프레임워크나 다중 Agent는 도입하지 않는다.
- 현재 모델이 없는 수집·계산 기준선을 완성한 뒤 RAG와 Agent를 비교할 수 있도록 한다. 합성 예제를 캐시 또는 실시간 금융자료로 표시하지 않는다.
- 10-K/A에 없는 값은 보류한다. 수정 공시가 재무 수치와 무관하다는 사실을 원문에서 검증하기 전에는 원본을 자동 채택하지 않는다.
- 전기 매출은 최신 선택 공시에서 찾는다. 직전 공시의 값과 다를 수 있으므로 재작성된 비교 수치를 조용히 섞지 않는다.
- 직접 비교 가능 판정은 기간·통화·정량 계정 조건에 한정된다. 기업들의 사업구조가 동질적이라고 주장하지 않는다.
- 화면은 흰색 바탕, 청색 강조 `#195CB0`, 잉크색 본문 `#17314D`, 옅은 청색 `#EDF3FA`, 보류용 황갈색 `#A66A00`을 사용한다. 한국어 시스템 글꼴로 왼쪽 정렬하며 비교표 아래 근거를 펼친다. 그림·애니메이션보다 보고기간과 수치의 가독성을 우선한다.
- 첫 버전의 동기 HTTP 읽기는 중단 확인 사이 최대 15초를 더 기다릴 수 있다. 기획의 엄격한 180초 종료 상한은 배포 전 취소 가능한 I/O로 전환해 검증한다.

## 검증의 경계

자동 테스트는 코드 회귀를 검증한다. 별도 정답셋, 라이브 연결, 원문 인용 정확도, 검토시간 30% 단축, 수치 정확도 95%는 각각 독립적으로 검증해야 한다. 현재 이러한 성과를 달성했다고 주장하지 않는다.
