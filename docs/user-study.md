# 담당자 검토시간 측정안

현재는 **미측정**이다. 아래 절차를 실제 사람이 수행하기 전에는 검토시간 30% 단축을 성과로 쓰지 않는다. 자동 실행시간은 사람의 원문 확인·수정 시간과 다르다.

1. 같은 난이도의 공시 검토 과제 열 개를 준비한다. 매출 확인, 영업손실 부호 확인, 이익률 검산, 전기 매출 선택, 증가율 검산, 결산기간 불일치, 기준일 이전 공시 선택, 수정 공시 설명, 위험 문단 인용, 보고서 수정으로 구성한다.
2. 절반은 수동 확인 후 Agent, 나머지는 Agent 후 수동 확인 순서로 수행한다. 두 번에 같은 답을 기억하는 영향을 줄이도록 과제별 회사·연도를 교차 배치한다. 연습 과제는 측정에서 제외한다.
3. 수동 조건에서는 같은 SEC 원문 묶음과 일반 계산기를 제공한다. Agent 조건에서는 같은 자료의 보고서와 원문 링크를 제공한다. 정답표는 참가자에게 미리 보여주지 않는다.
4. 시작은 과제 읽기, 끝은 검토자가 결과를 제출할 수 있다고 판단한 시점이다. 보고서 생성 대기, 원문 재확인, 계산 수정, 문구 수정, 잘못된 인용 수정 시간을 모두 포함한다.
5. 품질은 기간·단위·값·인용·보류 판단의 같은 체크리스트로 확인한다. 잘못된 결과를 빨리 제출한 경우 시간 개선으로 인정하지 않는다. 미완료와 시간 초과도 남긴다.
6. 과제별 두 조건 시간과 수정 횟수를 남긴다. 중앙값 감소율은 `(수동 중앙값 - Agent 중앙값) / 수동 중앙값 × 100`으로 계산하고 품질 통과율도 함께 보고한다.

기록 열: 익명 참가자 ID, 과제 ID, 사용 순서, 조건, 시작시각, 종료시각, 생성 대기초, 원문 확인초, 수정초, 전체초, 수정건수, 품질통과 여부, 실패 사유. 개인정보·녹음·화면 녹화는 필요하지 않다.

참가자가 개발자 한 명뿐이면 이를 명시한다. 한 사람·열 과제의 결과를 금융 실무자 전체의 생산성 향상으로 일반화하지 않는다. 자료를 이미 읽은 정도, 학습 효과, 과제 차이, 실행 환경을 결과에 함께 적는다.
