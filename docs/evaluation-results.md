# 동결 평가 v1 결과와 실패 분석

2026-10-12, 개발 20문항 점검 후 정답·코드·원문 목록을 동결하고 평가 40문항을 세 방법으로 실행했다. 총 120회 중 **80회 정상 완료·40회 API 429 실패**다. 뒤이은 최소 연결 진단에서 `credit_balance_exhausted / insufficient_quota`를 확인했다. 실패를 제거하거나 정상 보류로 바꾸지 않았다. **서비스 잔액에 의해 실행 범위가 달라져 방법 간 성능 우위를 판단할 수 없는 평가**다.

API 잔액과 프로젝트의 비용 상한은 서로 다르다. 전체 개발 실험 장부는 연결 진단까지 436호출, 보수적 예산 환산 812.8835원, 미확정 비용 0건이다. 실제 카드 청구액이나 API 계정 전체 사용액이 아니며, 다른 프로젝트 지출은 알 수 없다. 사용자 한도는 요청당 500원·전체 50,000원이다.

## 실패를 포함한 전체 결과

| 방법 | 실행 완료 | 수치 정답/응답 | 수치 응답/전체 | 인용 타당 문항 | 올바른 보류 | 전체 평균 시간 | 40회 예산 환산 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 단일 요약 | 28/40 | 15/15 | 15/24 | 21/32 | 7/8 | 4.39초 | 219.47원 |
| 어휘 RAG | 30/40 | 17/18 | 18/24 | 24/32 | 6/8 | 4.22초 | 31.26원 |
| 제안 Agent | 22/40 | 12/12 | 12/24 | 14/32 | 6/8 | 4.39초 | 34.99원 |

수치 정확도는 정답/응답, 응답률은 응답/24다. Agent의 조건부 수치 정확도 12/12=100%만 단독 성과로 제시해서는 안 된다. 응답률은 12/24=50%, 전체 수치 정답률도 50%다. 인용은 수치·서술 32문항을 분모로 하며 응답 실패와 누락도 실패다. 서술 문항 24회 모두 감사했고, 실제 답변이 있어 의미를 검토한 것은 16회다.

Agent의 내부 목표 중 수치 정확도 95%는 응답된 부분에서만 충족했다. 유효 응답률 80%(실제 50%), 인용 95%(14/32=43.75%), 보류 8/8(실제 6/8)은 미달이다. 작은 응답 표본과 실행 누락을 고려하면 품질 목표 전체 달성을 주장할 수 없다.

실행 실패는 단일 요약 12·RAG 10·Agent 18회이며 모두 HTTP 429다. 동결 채점기의 `errors` 필드는 바깥 예외만 세므로 Agent의 0은 실패가 없다는 뜻이 아니다. 공개 집계는 실제 execution 상태를 추가해 이 차이를 명시한다. 전체 평균 시간에는 빠르게 종료한 오류가 포함되므로 사용자 성공 체감 속도나 방법 간 속도 우위로 해석하지 않는다.

## 결과가 나온 문항에서 확인한 오류

- E24 RAG: NVIDIA 2026-01-25 종료 공시의 매출증가율을 65.48%로 계산했다. 원문 금액 215,938·130,497백만 USD의 정확한 산식 결과는 65.47353579…%다. 오차 0.006464…%p로 사전 허용치 0.005%p를 넘어 실패다. 올바른 반올림은 65.47%이며 원문 셀 인용 자체는 맞았다.
- E31 Agent: 중국 수출 제한의 핵심 설명은 맞지만 중국 규제 당국의 **예비 판단(preliminary finding)**이라는 한정을 생략했다. 의미 검토에서 인용 타당성 실패로 기록했다.
- E30 Agent: 원자재·생산·검사 능력 부족의 핵심 위험은 맞다. 다만 추가한 **제한된 수의 업체에 의존**한다는 문구가 연결된 단일 문단에는 없어 해당 답변의 인용 타당성을 실패로 판정했다. 정확한 구절 일치만으로 설명의 모든 내용을 보증할 수 없음을 보여준다.
- 개발 D15 Agent: 서로 떨어진 두 문장을 하나의 정확 인용처럼 결합해 검증을 통과하지 못했고 호출 한도에 도달했다. 개발용 실패이며 동결 평가 수치와 합치지 않는다.

## 해석 범위와 다음 평가

원문 금액을 별도로 전사했지만 정답 작성·서술 검토를 개발 보조 AI가 수행했다. 외부 전문가 독립 검수는 없다. 같은 세 기업의 관련 공시군, 각 방법 한 번, 같은 추출기 공유, 서로 다른 문맥 길이와 호출 수의 한계가 있다. 전체 10-K 무제한 요약이나 임베딩 RAG와의 비교가 아니다. 사용자 검토·수정 시간과 30% 단축 효과는 미측정이다.

잔액 복구 뒤 재실험한다면 v1 실패를 보존하고 별도 실행 버전과 시작 전 계획을 남긴다. 실패 문항만 채워 이전 성공과 합쳐 좋은 결과를 만들지 않는다. 코드를 바꾸면 새로운 동결 해시를 사용하며 v1 결과를 대체하지 않는다. 현재 파일은 제출 검토용 중간 결과이고, 안정적인 API 실험 완료나 우수한 모델 품질을 선언하지 않는다.

재현 절차와 채점 정의는 [평가 프로토콜](../evaluation/README.md), 집계는 [results-v1.json](../evaluation/results-v1.json), 원문·코드 지문은 evaluation/corpus.json과 freeze.json에 있다. 개별 응답·동결 원문은 Git에 올리지 않고 로컬에 보존한다.

로컬 보존 ZIP을 별도 폴더에 해제하고 새 Python 3.13 가상환경에서 API 호출 없이 재채점해 원래 집계와 모든 값이 같은 것을 확인했다. 이 검사는 저장 응답 채점의 재현이며 새 모델 실행이나 금융 정확도 검수가 아니다. 원문·코드·결과를 포함한 ZIP에는 키·연락처·비용 장부를 넣지 않았다.
