# GPT 클라우드에서 개발 이어가기

2026-10-12 사용자 요청은 컴퓨터를 꺼도 GPT가 개발·오류 점검을 계속하는 것이다. 별도 서버 구매 없이 현재 ChatGPT 요금제의 사용 한도 안에서 시작한다. 같은 프로젝트의 ‘클라우드 검사 결과’ 채팅에서 첫 오프라인 검사를 완료했으며, 2026-10-13 실제 명령·종료 코드·출력을 대조했다. 아래 검사 범위와 남은 조건을 구분한다.

## 작업 범위

- 예선 기획안은 이미 제출했으므로 수정·교체·재제출하지 않는다. v4는 내부 참고본이다.
- 현재 작업은 실행 화면 개선과 재현 가능한 오류의 점검·수정이다. 추가 기능·전체 재평가·공개 앱 배포는 1차 심사 합격 이후 진행한다.
- 클라우드 초기 점검에는 API 키를 넣거나 유료 API를 호출하지 않는다. 오프라인 검사와 합성 예제로 시작한다.
- 실제 데이터·합성 예제·내부 검사·독립 평가를 구분한다. 동결 v1 평가 결과를 수정하거나 새 성공 사례와 합산하지 않는다.

## 코드와 실행 환경

저장소: [juyoo0729/ProofResearch](https://github.com/juyoo0729/ProofResearch), 기준 브랜치 `main`. 작업을 시작할 때 실제 커밋을 기록하고 `AGENTS.md`, `README.md`, `docs/implementation-plan.md`를 먼저 읽는다.

클라우드의 작업 폴더에 저장소를 가져오고 Python 3.12와 uv 0.12.4를 준비한다. 로컬 컴퓨터에 연결된 실행 도구나 D: 경로에 의존하지 않는다. 저장소 루트에서 기존 CI와 같은 명령을 실행한다.

```sh
uv sync --frozen --extra dev
uv run pytest
uv run proofresearch sample
```

필요한 패키지를 설치할 수 있는 네트워크 접근이 필요하다. 설치·검사·합성 예제가 실제 클라우드 실행 도구에서 완료된 뒤에만 컴퓨터를 꺼도 이어갈 준비가 되었다고 보고한다. 클라우드에서 명령을 실행할 수 없으면 로컬 도구로 대신 실행하지 말고 필요한 환경 설정을 설명한다.

## 가져오지 않는 로컬 자료

`.env`, API 키·SEC 연락처, `.cache/`의 원문·비용 장부, `reports/`, `결과물/`은 GitHub에 포함되지 않는다. 클라우드에 없다는 이유로 기록을 새로 만들거나 제출본을 다시 작성하지 않는다. 특히 빈 비용 장부로 기존 50,000원 예산을 새로 시작하지 않는다. 실제 API 검증을 옮길 때는 기존 사용량·영속 저장·단일 실행 환경을 별도로 확인한다.

중요한 코드 변경은 Git에 기록하고 결과를 저장한다. 클라우드 작업 공간의 저장 상태만을 영구 백업으로 취급하지 않는다. 검사가 통과했다는 사실은 측정된 제품 정확도나 공개 배포 완료를 뜻하지 않는다.

## 첫 클라우드 작업의 완료 조건과 확인

1. 연결된 개인 컴퓨터 없이 클라우드에서 저장소를 확보하고 현재 커밋을 확인한다.
2. 위 설치·검사·합성 예제의 실제 결과를 기록한다. 이전 Windows/CI 결과를 새 클라우드 결과로 쓰지 않는다.
3. 재현 가능한 오류를 찾으면 최소한으로 수정하고 관련 검사를 수행한다. 변경 내역, 남은 문제와 저장 위치를 보고한다.

## 결과 보존과 남은 조건

클라우드에서 문서 커밋 `4171dcf9451b0d67d6da7e982b194aa25df5003a`와 `ProofResearch-cloud.bundle`을 생성했지만 터미널의 GitHub push는 쓰기 인증 부재로 실패했다. 2026-10-13 저장소의 최신 문서에 검사 출력을 대조해 기록을 반영했다. 개인 컴퓨터의 브라우저 로그인은 클라우드 터미널에 자동으로 공유되지 않는다.

### 연결된 GitHub 앱으로 저장

2026-10-13 이 로컬 Codex 채팅에서 연결된 GitHub 앱의 계정·저장소 쓰기 권한을 조회하고, 같은 앱의 Git 데이터 API로 이 문서와 상태 문서를 저장했다. 저장소 읽기 확인만으로 쓰기 성공을 주장한 것이 아니다. 개인 컴퓨터의 Git 자격증명이나 API 키를 클라우드로 복사하지 않았다. 클라우드 터미널의 `git push` 인증을 설정한 것은 아니며, 기존 클라우드 채팅에서도 같은 앱 도구를 사용할 수 있는지와 실제 저장 여부는 아직 재현하지 않았다.

후속 클라우드 작업에서 GitHub 앱 도구를 사용할 수 있으면 다음 절차로 결과를 보존한다.

1. 대상 저장소와 최신 `main`을 읽고, 수정·검사를 마친 파일만 준비한다. 비밀·연락처·캐시·원본 제출물·실행 보고서는 제외한다.
2. 한 파일은 현재 파일 SHA를 확인한 뒤 갱신한다. 여러 파일은 기존 트리를 바탕으로 새 트리·커밋을 만들고, 예상 브랜치 SHA가 여전히 같을 때만 강제 갱신 없이 반영한다. 충돌하면 최신 변경을 먼저 확인한다.
3. 성공 응답 뒤 원격 커밋·파일을 다시 읽어 저장을 확인하고 실행 환경의 코드를 동기화한다. 앱 도구가 없거나 쓰기에 실패하면 작업 결과와 Git bundle을 보존하고, 저장 완료로 보고하지 않는다.

클라우드의 첫 검사 작업과 후속 설명은 완료 상태다. 현재 진행 중인 검사나 상시·예약 작업은 없다. 클라우드에서 새 작업을 요청해 이어갈 수 있으나, 무기한 자동 개발·공개 앱 서버 운영이 설정되었다고 해석하지 않는다. 기존 평가의 인용 의미 타당성과 API 실패는 이번 오프라인 검사로 해소되지 않았다.
