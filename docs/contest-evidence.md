## 제출 체크리스트

- 예선: **2026-11-12 10:00 KST**, 공식 양식 **10쪽 이내 PDF**. 기존 기획안을 현재 증거와 미측정 항목으로 갱신한 뒤 렌더링·페이지 수를 검사한다.
- 예선 점수: 전문가 70%·상호 평가 30%. 상호 평가 **11-12 12:00 ~ 11-19 10:00 KST**. 공식 평가 화면에는 최소 투표 미달 시 투표·득표가 평가에 반영되지 않는다고 적혀 있으나, **구체적인 횟수는 현재 기재되어 있지 않다**. 평가 시작 전 공지·화면에서 확인한다. 참가자가 직접 투표한다.
- 본선: **2026-12-22 10:00 KST**, 실행 가능한 데모 URL·GitHub 코드/가이드·발표 PDF. 시연영상은 선택 가산점 항목으로 준비한다. 발표 10분·질의응답 10분.
- 비공개 키와 연락처, 요청당/전체 예산, 여러 프로세스의 SEC 접근 제한을 배포 환경에서 확인한다. 공개·최종 제출은 사용자 허용 범위 안에서 수행한다.
- 현재 상태는 **개발 및 제출 준비 중**이다. 코드·테스트 통과, 파일 작성, 준비 완료, 최종 제출 완료를 서로 바꾸어 표현하지 않는다.

## 성과로 주장할 수 없는 항목

개발 20/동결 40 정답셋을 작성하고 세 방법 120회를 시도했지만, 40회는 API 잔액 오류로 실패했다. Agent 응답률 50%·인용 타당 문항 43.75%·보류 6/8로 전체 목표에 미달했다. 답변된 수치만 12/12라고 전체 정확도 달성을 주장하지 않는다. 기준선 대비 우위, 외부 독립 정확도, 검토시간 30% 단축은 입증되지 않았다. [실패 분석](evaluation-results.md)에 전체 분모·검토 한계·재평가 조건을 기록했다.

현재 로컬 검토안과 실제 제출 전 조건은 [제출 자료 목록](submission-checklist.md)을 따른다.
