# 제출 현황과 이후 점검

**예선 기획안은 제출 완료이며 수정하지 않는다**(2026-10-12 사용자 확인). 제출본의 버전·접수 내역은 별도로 확인하지 않았다. 로컬 파일은 공개 코드 저장소에 올리지 않고 `결과물/`에 보존한다.

현재 1차 심사 전 작업은 화면 디자인·오류 점검이다. 제출 상태를 잘못 이해하고 만든 v4는 내부 참고본으로만 보존하며, 제출본 교체나 재제출에 사용하지 않는다. 추가 기능·전체 재평가·서버 구매·공개 배포는 사용자 결정에 따라 1차 심사 합격 확인 이후로 보류한다.

예선 v1·v2·v3와 본선 v1은 이전 버전으로 보존했다. 실제 예선 제출본과 로컬 버전의 대응 관계는 확인하지 않았다. 본선 자료·대본·영상은 합격 후 갱신할 검토안이다. 영상은 실시간 실행 녹화가 아니며, 로그 당시 21개 지표와 현재 24개 지표를 구분한다. 로컬 `검토자료_검증기록_v4.json`은 내부 참고본 v4를 만들 때의 해시와 검증 기록이다.

## 제출 이후 유지할 기준

1. 예선 제출본을 수정하거나 교체하지 않는다. 후속 구현·API 점검 결과가 제출본에 포함되었다고 추정하지 않는다.
2. v1의 80회 완료·40회 오류와 의미 인용 실패 두 건을 유지한다. API 복구와 후속 단일 분석은 별도 작동 점검이며, 방법 간 우위·품질 목표 달성·검토시간 30% 단축의 증거로 사용하지 않는다.
3. 유료 실행이 필요하면 모델 가격 기록의 유효기간을 확인한다. 코드의 가격 기록은 30일간 유효하며, 확인 없이 날짜만 연장하지 않는다.
4. 2026-10-12 공식 안내와 평가 화면에서 재확인한 일정은 예선 마감 11월12일 10시, 상호 평가 11월12일 12시~19일 10시, 본선 마감 12월22일 10시(KST)다. 상호 평가·본선 참여 전 변경 공지를 다시 확인한다. 구체적인 최소 투표 횟수는 여전히 미기재이며, 참가자가 공지·투표 화면을 확인하고 직접 투표한다.
5. 본선 접수는 아직 완료하지 않았다. 예선 제출 완료와 본선 자료 준비·접수를 구분한다.

## 1차 심사 합격 이후

1. 기존 코드·정답·원문·응답을 보존한 v1과 구분하여 별도 전체 평가를 수행한다. 새 결과로 본선 자료·대본·영상을 갱신한다.
2. 외부 검토와 담당자의 원문 확인·수정 시간을 포함한 사용성 과제를 수행한다. 미측정 효과를 성과로 보고하지 않는다.
3. 공개 데모의 대상·호스팅·별도 운영비·비밀 설정과 배포 허용 범위를 확정한다. 단일 런타임과 영속 비용 장부를 유지하며 실제 외부 URL에서 세 흐름을 점검한다.
4. 발표·질의응답 리허설, 공개 영상 게시 및 본선 최종 접수를 별도로 완료한다.

공식 근거와 평가 항목 매핑은 [contest-evidence.md](contest-evidence.md), 환경은 [deployment.md](deployment.md), 실험 한계는 [evaluation-results.md](evaluation-results.md)에 있다.
